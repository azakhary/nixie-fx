# Soft particles review (#3392)

This is an editable NixieFX project **and** a small game-owned Three consumer.
The consumer loads the compiled `out/vfx` bundle through `loadVfxExportBundle`;
it never uses source effect JSON. The game owns its scene, camera, renderer,
opaque props and animation loop.

## Run the paired branches

Use `codex/3392-soft-particles` in both `nixie-fx` and `vfx-editor`.
From sibling repository folders:

```sh
cd nixie-fx
npm ci
mkdir -p ../.local-packages
npm pack --pack-destination ../.local-packages
node dist/cli.js validate examples/soft-particles
node dist/cli.js export examples/soft-particles
cd ../vfx-editor
npm ci
npm install --no-save ../.local-packages/nixie-fx-0.1.24.tgz
npm run dev -- --force --host 127.0.0.1
```

Open **http://127.0.0.1:8080/** → **Open Folder** and select
`nixie-fx/examples/soft-particles` (the folder containing `vfx-editor.prj`).
Select Three, enable **Lit**, and choose `intersections` in **Preview scene**.
Open **Assets → Particle Effects** and double-click an effect. Select its
emitter in the timeline and expand **Renderer** in the right inspector.

In a second terminal:

```sh
cd nixie-fx/examples/soft-particles
npm install --no-save ../../../.local-packages/nixie-fx-0.1.24.tgz
npm run dev
```

Open **http://127.0.0.1:8086/**. The footer names the **actual** backend,
Three revision and depth-pass count. The backend menu also forces the supported
WebGL2 fallback. The consumer's toggle and distances apply to all its
transparent emitters, while the editor edits each emitter independently.

No package version has been published. Install the local tarball again after
runtime edits and restart Vite with `--force`; do not use `npm link`.

## Project files and checkpoints

- `effects/smoke.json`: textured smoke around the floor and two cubes.
- `effects/glow.json`: cyan additive glow in the same scene.
- `effects/materials.json`: normal/additive/premultiplied graph materials,
  lit/unlit paths, a mesh particle, Opaque/Masked controls, a legacy-color
  graph, a second emitter sharing the normal material with fading disabled,
  and stock lit particles with trails.
- `assets/scenes/intersections.scene`: opaque floor, near cube, far cube.
- `effects/thresholds.json` + `assets/scenes/checkpoints.scene`: three fixed
  particles in front of the wall's Z=0 surface. Use a straight-on front camera
  (looking toward -Z), Near **0.25**, Far **1**. Left: gap 0.25, zero
  contribution. Center: gap 0.625, half contribution. Right: gap 1, original
  appearance. The consumer sets this camera when choosing Thresholds; set
  Near to 0.25 there. At time 0, advance slightly to emit the burst.
- `out/vfx/manifest.json`: complete exported bundle, regenerated by the CLI.
- `main.ts`: minimal public API integration and host-owned floor/cubes.

Smoke is saved with the fade enabled for review. Newly created emitters and
older effects without settings default to **off**, Near **0**, Far **1**.
The procedural smoke texture is a test asset; the glow and box fixtures come
from this repository's existing examples.

## Quick human review / recording flow

1. Smoke + intersections: pause, toggle off/on at the same seed/time. Compare
   seams at the floor/cubes, texture detail farther away, and empty background.
2. Change Far from 0.25 to 1, then Near from 0 to 0.2. Try negative, equal and
   reversed values. Undo/redo, duplicate, save, close and reopen.
3. Orbit, change perspective/orthographic, resize, and toggle Bloom. Repeat
   with Glow and Materials. Only the selected emitter's setting should change;
   Opaque/Masked explain why fading is unavailable. Trails keep their appearance.
4. In Pixi, verify the unavailable hint and unchanged rendering; return to Three
   and verify the settings remain. Repeat Three with WebGL and WebGPU.
5. Use Thresholds for the three exact gap checkpoints, then repeat the main
   intersection comparison in the exported consumer, including WebGL2 fallback.
6. Record the editor controls, actual backend, distances, same-time off/on
   comparison, camera movement, additive glow and exported consumer. Human
   review/recording is intentionally left to the requester.

See [verification results](../../docs/soft-particles-verification.md) for
measured coverage and the 60 Hz mirrored-display limitation.
