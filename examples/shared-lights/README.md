# Exported shared-light consumer

This example has no editor dependency. It loads `public/vfx/manifest.json` and
its effect JSON through `loadVfxExportBundle`, plus the review scene and geometry.
Three separate `ThreeVfxRenderer` clients each instantiate the same exported
effect; all register with one scene-wide `ThreeVfxLightManager`.

Use the matching `codex/2214-shared-particle-lights` branches in `nixie-fx` and
`vfx-editor`. From the runtime repository:

```sh
npm ci
mkdir -p ../.local-packages
npm pack --pack-destination ../.local-packages
cd examples/shared-lights
npm install --no-save --package-lock=false ../../../.local-packages/nixie-fx-0.1.17.tgz
npm run dev -- --port 8084
```

Open `http://127.0.0.1:8084/`. Vite also prints the local-network URL; open that
URL on a physical phone connected to the same network. Keep the tab visible.
This example uses the actual device DPR; it does not lower quality to hit a
frame target. Budget 0 removes only VFX illumination. The separate Game Light
slider changes a host-owned directional light. The scene's ambient light also
continues to work. Both are reserved independently before choosing the VFX
allowance; their count is displayed separately. See
[`docs/particle-lights.md`](../../docs/particle-lights.md) for the integration
contract, lifecycle rules, selection/fade behavior, and reservation policy.

For matching editor data, open `docs/qa/particle-lights/vfx-editor.prj` in the
editor repository. The checked-in consumer export was generated by the normal
`writeVfxExportFromProject` pipeline. To regenerate from the supplied public
fixture, install the local runtime package in the editor and run, from the
editor repository:

```sh
node scripts/prepare-light-review.mjs ../nixie-fx/examples/shared-lights/public
```

Adjust the output argument when the runtime checkout is elsewhere. This
fixture regeneration intentionally resets the review project's authored data;
copy an artist-edited project before using it. The consumer needs only the
normal compiled export and the two scene assets; it never reads `.prj` or
editor source at runtime.

## Review

- Compare budgets 0, 2 and 4 with bloom off. Moving warm/blue illumination
  should change the floor, wall and block. Active includes retiring fade slots
  and must remain at or below the shared budget across all instances.
- Pause, seek and restart. Pause holds the light state; seeking rebuilds it.
  Enable 2/4 while paused at budget zero to verify immediate restored lighting.
- Remove all three instances, then add them repeatedly. Candidate and active
  counts must return to zero and the game-owned lights must remain.
- Toggle Heavy Light Overlap. It brings instances together without changing
  light radii or authored definitions. Compare the same workload at 0/2/4.
- The consumer pauses rAF when its document is hidden and releases registrations
  and rendering resources on page teardown.

After at least 10 seconds of warmup, use **Measure 30 seconds** for each budget.
The report includes browser/GPU, DPR/resolution, workload, frame lows/spikes,
CPU simulation/selection, render submission and total work. Repeat budget 4
with Heavy Light Overlap, and repeat after several minutes of sustained play.
CPU render submission is not a GPU timer. Copy Measurements works on secure
origins (including localhost); on an HTTP phone URL, select and copy the JSON
manually if clipboard access is unavailable. Record phone model/OS and display
refresh separately; these cannot be reliably inferred from user-agent strings.
Apply the 90fps/13ms flags to a 120Hz desktop only, not a 60Hz phone.

The human reviewer records and uploads proof footage. This example creates
no screenshots, recordings, Wagglet attachments or task-status changes.
